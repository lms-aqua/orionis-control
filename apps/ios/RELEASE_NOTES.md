Orionis Control 1.0.0 makes the camera list yours to change. Until now the sources the gateway pulled from were fixed at deployment: adding a camera system meant editing environment variables on the server and restarting it. There is now a Connections screen in Settings, and what the app shows comes from sources you add, edit and remove from the phone. Cameras from every enabled source appear together on one wall, grouped by where they came from, and a source that goes down takes only its own cameras with it rather than blanking the others.

Seven kinds of source are supported. Frigate is the fullest — cameras, object-detection events, recordings and snapshots. UniFi Protect brings cameras, snapshots and live view over RTSPS. Wyze works through a docker-wyze-bridge instance, TP-Link Tapo over the camera's own local RTSP account, Blink through a lostblink bridge, and Google Nest through the Device Access API. A plain RTSP URL or a go2rtc instance covers everything else. Each one states what it can actually do before you add it, and the app hides what it cannot: a source with no event history does not get an Events tab that returns an empty list, because an empty list reads as "nothing happened" rather than "this cannot be asked".

Adding a source is a form the server describes rather than a screen written per manufacturer, so a source type added to the gateway appears in the app without an app update. Each source is checked the moment you save it, so you learn immediately whether it works instead of finding out at the camera wall — and when it does not, the screen says what the upstream actually replied. A console with a certificate this server does not trust, a Nest refresh token that was revoked, a camera whose RTSP channel is switched off: each reads as itself rather than as a generic failure.

Credentials for those systems are encrypted on the gateway and never sent back to the app. An existing password shows as "Saved" and stays untouched unless you type over it, the whole Connections area is administrator-only and audited, and every address you enter is checked before the server will fetch it. Sources that sign in interactively — Blink, and anything else that mails or texts a code — are a real step in the app now, showing the same code prompt the vendor's own app does, rather than asking you to paste a secret into a settings field.

Settings itself is easier to move around. Search covers every control by name, by the words you might use instead, and by the screen it lives on, so "mute", "grid" or "do not disturb" land on the right switch. Text through Settings and Connections now scales with your Dynamic Type setting, the status indicator no longer pulses when Reduce Motion is on, progress overlays become solid under Reduce Transparency, and each row reads as a single item to VoiceOver instead of four separate stops.

Two things are worth knowing before relying on this. The UniFi Protect, Tapo, Wyze and Nest connections are written to each vendor's published API and have not yet been run against that hardware; if one misbehaves, the fault is more likely in how its responses are read than in the app around it. And Nest needs a Device Access project, which Google charges a one-off fee for — the app cannot avoid that — while its newer cameras stream over WebRTC in a way this release does not yet open, which those cameras say plainly rather than failing silently.
